    Accessibility, in plain terms.

    This page lists exactly how this website behaves with a screen reader, a keyboard, a magnifier or reduced motion — no vague promises, just what is actually wired up. Every item is “Live” because it ships in the page you are reading right now.

    The exhaustive list

    Every accessibility feature on this site.

    Grouped by what you might be using to read it. If something here doesn't hold up for you, that is a bug — please tell us.

    Screen readers & VoiceOver Live

    • VoiceOver (iOS/macOS), TalkBack (Android), NVDA and JAWS (Windows), Narrator and Orca (Linux) all read this site through the same standard semantics — nothing here is built for one reader only.
    • Every control is a real <button> or <a>, so it is announced with its role and state and lands in the reader's element list.
    • Icons that carry no meaning are marked aria-hidden; icons that do carry meaning have a text label, so a reader never announces “graphic” with nothing after it.
    • Live regions announce toasts and search results politely, without stealing focus.

    Full keyboard operation Live

    • Everything is reachable and operable with Tab, Shift+Tab, Enter, Space and the arrow keys — there is no action that needs a mouse.
    • A Skip to content link is the first thing you reach, so you can jump the navigation on every page.
    • The carousel arrows, flip cards, menus and dialogs all take focus in a logical order and never trap it.
    • Escape closes the search overlay, the full-screen viewer and the mobile menu.

    Visible focus, always Live

    • A clear, high-contrast focus ring follows the keyboard on every interactive element — it is never removed, only styled.
    • Focus rings show for keyboard users and stay out of the way for mouse users, via :focus-visible.
    • When a dialog opens, focus moves into it; when it closes, focus returns to the control that opened it.
    • Focus is never sent to something hidden — collapsed panels are marked inert so they can't be tabbed into.

    Respects reduced motion Live

    • Turn on Reduce Motion in your system settings and the auto-scrolling carousel stops moving on its own and becomes a plain, swipeable row.
    • Reveal-on-scroll animations, card flips and hover lifts all shorten to nothing — content simply appears.
    • The carousel can also be paused by hand with the pause button, and pauses itself on hover or focus.
    • No animation flashes, and nothing moves faster than three times a second.

    Colour & contrast Live

    • Body text and interface controls meet or beat the WCAG AA contrast ratio in both the dark and light themes.
    • Colour is never the only signal — states also carry an icon, a label or a shape.
    • The design leans on tokens with a separate text-ink colour, so buttons stay legible when the theme flips.
    • Nothing depends on distinguishing red from green.

    Dark, light & system themes Live

    • The site opens in whichever theme your device prefers, and remembers your choice after that.
    • A theme toggle in the header switches dark and light instantly, applied before the page paints so there is no flash.
    • Both themes are first-class and both are contrast-checked — the light theme is not an afterthought.
    • Device mockups stay dark in either theme on purpose, so they read as a phone screen, not a page element.

    Text size & zoom Live

    • Zoom the browser to 200% and beyond — the layout reflows into a single column instead of scrolling sideways.
    • Text is sized in relative units, so it grows with your browser's font-size setting.
    • Wide things — tables, code, diagrams — scroll inside their own box, so the page itself never scrolls horizontally.
    • There is no fixed, viewport-locked text that would clip when enlarged.

    Comfortable pointer targets Live

    • Buttons and links are sized to a comfortable touch target with room around them, so they are easy to hit.
    • Tapping works the same as clicking — nothing depends on hover to be usable.
    • Nothing needs a precise drag, a long-press or a multi-finger gesture.
    • Hover and focus reveal the same information, so touch users are never shown less.

    Semantic, predictable structure Live

    • One <h1> per page and headings that step down in order, so a reader's heading list is a real outline.
    • Landmarks — banner, nav, main, contentinfo — let you jump straight to a region.
    • The current page is marked aria-current in the navigation.
    • Every page declares its language, and the reading order matches the visual order.

    Save any screen as an image Live

    • Every device mockup carries a small download button, and a full-screen view button, in its corner.
    • The full-screen viewer has its own download button and closes with Escape or the close control.
    • Images are rendered on your own machine from the page itself — nothing is fetched from a server to do it.
    • Both buttons have text labels for screen readers even though they show only an icon.

    Take the words with you Live

    • The news archive has Download all images and Copy all text buttons that act on every visible post at once.
    • Copied text keeps its headings, tags and dates as plain text you can paste anywhere.
    • All body text is real, selectable text — none of it is baked into an image.
    • A short status message confirms what happened after each action.

    Nothing hidden from assistive tech Live

    • Expandable cards and FAQ rows report their open or closed state with aria-expanded.
    • Collapsed content is genuinely removed from the tab order and the accessibility tree until it opens.
    • No content is available only on hover, and none of it disappears before you can read it.
    • The site works with JavaScript doing less — the core reading experience does not depend on it.
